# ALPHA TESTING - COMPANION MOBILE APP

**System:** Health Kiosk System with IoT Sensors, Data Analytics and Companion Mobile Application
**Test Type:** Alpha Testing (Internal)
**Scope:** Android companion application (SMCBI VitalSync)
**Build under test:** app-arm64-v8a-release.apk, Expo SDK 54, package com.hansieee.smcbihealthkioskmobile
**Pre-Condition:** Login & Registration, User-Side and Admin-Side alpha testing completed and cleared.

**Status:** FINALIZED - the question set is closed. Revisions from here on need a new version.

**Tester Name:** ______________________  **Testing Date:** ______________  **Testing Time:** __________

Questions are numbered **Q1-Q62 in final testing order**. Each section of the Alpha Testing keeps its
own numbering, so a question is identified by its section and number together.

Admin-side coverage of the companion app lives in **Admin-Side TC-11 (Q63-Q68)** - sign-in, the
reading appearing, the manual sync, deletion revoking access and offline creation - and is
deliberately not repeated here. This document covers behaviour inside the app.

The test cases follow the app from top to bottom, and every test case begins by navigating to its
screen, so the run never jumps between screens without saying so.

> Mark the result for every step performed, and write anything unusual under **Comment**.
> Use **Additional Test / Observation** for anything the predefined steps do not cover.
> A step that was not actually run must be left blank.

## Known and already logged - do not raise these as new defects

| Item | Detail |
| --- | --- |
| Notification says ALERT for a Watch record | Fixed in the Edge Function on 2026-08-18, but it only takes effect once `send-measurement-push` is redeployed. The kiosk itself already reports Watch as Watch. |
| Deleting a student leaves the `public.users` row | 42501 / HTTP 403. `GRANT DELETE ON public.users TO service_role` is the fix; confirm it has been applied before testing deletion. |
| Older records show "NOT REVIEWED" | Records synced before `measurement_statuses` existed carry no verdict. Unknown is not the same as healthy, so this is correct. It is not permanent - a re-sync backfills the verdict. |
| Flagged count lower than the old "Warning Records" | The old count treated Watch and Incomplete as warnings against hardcoded thresholds. It now reads the clinic's verdicts. Lower is the fix working. |
| Push does not work in Expo Go | Removed from Expo Go on Android in SDK 53. Test push on the APK only. |
