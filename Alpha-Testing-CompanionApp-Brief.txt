## 6. Integration contract — the facts you need

**Cloud:** Supabase. The kiosk pushes to it; the app reads from it.

**Auth:** Supabase Auth (GoTrue). A student account is created through
`/auth/v1/admin/users` by the kiosk. The app signs in with the school email and
password. Passwords and password hashes exist only in Supabase Auth; the
`public.users` profile row intentionally has no `password` column.

**Accounts:** email domain `@smcbi.edu.ph`. Default password when an admin
creates the account is `<Firstname>12345` — first name with spaces removed,
e.g. `Hans12345`. Email is auto-verified on admin-created accounts.

**Table `public.users`** — one row per account, upserted on `local_user_id`:

    local_user_id, auth_user_id, firstname, lastname, student_id, email,
    role, department, grade_level, strand, year_level, program,
    age, gender, barcode, is_active, created_at, updated_at

  role         : student | personnel | admin
  department   : students  -> COLLEGE, BED
                 staff     -> COLLEGE INSTRUCTOR, BED INSTRUCTOR, NTP
  is_active    : false must block the app the same way it blocks the kiosk

**Table `public.health_records`** — one row per kiosk session, upserted on
`local_health_record_id`:

    local_health_record_id, local_user_id, auth_user_id,
    local_kiosk_session_id, session_number, session_status,
    heart_rate, spo2, temperature, height, weight, bmi, bmi_category,
    health_status, measurement_statuses, missing_measurements,
    recorded_at, created_at, updated_at

**Table `public.user_push_tokens`** — companion-app devices, keyed by `token`:

    token, auth_user_id, platform, device_name, last_seen_at, created_at

**Important — do not display `health_status` on its own.** It collapses a whole
session into one word, and completeness outranks severity: a 40 °C reading taken
during an unfinished session is stored as `Incomplete`, which hides the alert.
Use `measurement_statuses` for the per-reading verdict, e.g.
`{"temperature": "Alert", "spo2": "Normal"}`.

**Grading bands are set by the administrator and can change.** These are the
current values; read them as configuration, never hardcode them:

    temperature : Alert < 35, Normal 35 – 37.2, Alert > 37.2   (°C)
    heart rate  : Alert < 60, Normal 60 – 100, Alert > 100     (bpm)
    SpO2        : Alert <= 90, Watch 91 – 94, Normal 95 – 100  (%)
    BMI         : underweight <= 18.4, normal <= 24.9, overweight <= 29.9

When an admin changes a band, the kiosk re-grades every stored record and
re-raises or retires the matching notifications and alerts. The app should
reflect the stored grade rather than computing its own.

**Deletion:** deleting an account in the admin portal deletes the Supabase Auth
user, which is what blocks the app from signing in.

## 7. Two known issues on the web side — expect them while testing

  1. **The profile row is not deleted from `public.users`.** The Auth user is
     deleted (so sign-in is correctly refused), but the profile delete returns
     403 / SQLSTATE 42501 because the service role lacks the grant. Until this
     is run in the Supabase SQL editor, a deleted student's row stays in the
     table:

         GRANT DELETE ON public.users TO service_role;

     Test sign-in refusal, and note the leftover row as a defect rather than
     treating it as your bug.

  2. **The admin account has no Supabase Auth user.** This is deliberate — the
     admin is kiosk-only and is not expected to sign in to the app.
